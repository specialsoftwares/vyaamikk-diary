## Remaining release blockers

1. **Storage authorization architecture.** See [STORAGE_AUTHORIZATION_BLOCKER.md](./STORAGE_AUTHORIZATION_BLOCKER.md). The selected Storage Rules still cannot carry the owner, session, restore, account, and deletion checks inside the production two-document budget, and they still do not match GRIN. Those rules were not changed and must not be deployed as the fix. The new source path is the callable `ownerObjectTransfer`: identity comes from the verified bearer, writes require an active account and a non-completed deletion job, and a GRIN original also requires the server object-key reservation in `reserved` or `uploading`. Bytes are PUT to a two-minute staging ticket and published only by commit, which sniffs the stored prefix and copies with a create-only generation precondition. Cleanup deletes that attempt's staging object only. A read ticket lasts 60 seconds and can still be fetched after a later revocation until it expires; commit and delete do not trust it. Firestore and Storage are not one transaction, and an unknown copy stays retryable. Production letterhead, attachment, PDF, and GRIN original transfers use this path. Direct Storage SDK helpers remain for emulator tests and the explicitly injected media-port adapter. Installed binaries keep using the current live rules until a separate compatibility decision; this source change does not tighten those rules. The callable is not deployed.
