## Remaining release blockers

1. **Storage authorization architecture.** See [STORAGE_AUTHORIZATION_BLOCKER.md](./STORAGE_AUTHORIZATION_BLOCKER.md). The selected Storage Rules still cannot carry the owner, session, restore, account, and deletion checks inside the production two-document budget, and they still do not match GRIN. Those rules were not changed and must not be deployed as the fix. Installed clients keep using direct Storage under the current live rules until a separate compatibility decision. Tightening those rules would break installed binaries. This source change does not do that.
   The callable `ownerObjectTransfer` is the new-client path. Identity comes from the verified bearer. Commit and abort are transactional: an abort that lands first stays aborted, and a commit that has reached `publishing` rejects the abort. Validation, copy, recovery, and cleanup use one staging generation, kept as a string. The upload ticket is create-once (`x-goog-if-generation-match: 0`). The production copy sends `contentType` and custom metadata as the rewrite body and accepts a generation only from a completed rewrite `resource` after a generation-bound read. Equal size and a shared 16-byte prefix are not identity. A lost copy response stays on the same attempt. Before a denial can fail that attempt, the server reconciles the published generation and deletes only that generation; an uncertain delete stays `publishing` with the generation recorded. A PUT that stores no bytes stays `validating` until the upload deadline and can still publish if those bytes arrive. After the deadline, with still no bytes, the attempt expires and the client may begin a different attempt. A timeout or an abort that does not settle does not cancel the server operation, does not report the object as deleted, and does not start a second attempt while publication could already have succeeded.
   Session cutoff, restore closure, account state, deletion, and a GRIN reservation are rechecked before the copy and again before the attempt is marked committed. Firestore and Storage are not one transaction. Generic read and delete of a GRIN original are denied; reserve, begin, upload, and verify stay on the GRIN lifecycle. A read ticket lasts 60 seconds, is bound to the generation it was signed for, and is not cancelled when the session ends. Callers receive `expiresAt` so they can refresh. The ticket is not immediately revocable.
   Production letterhead, attachment, PDF, and GRIN original uploads use this path. Direct Storage helpers remain for emulator tests and an explicitly injected media-port adapter. The callable is not deployed. Deploying only `ownerObjectTransfer` would not show that earlier recovery, mailbox, quarantine, or GRIN corrections are serving.
